# FF 应用层 SDK 1.0.1：快速开始（未正式发布）

目标环境：Windows x64、Visual Studio 2019 v142、C++17。把 `include` 加入包含目录、`lib/x64/Release` 加入库目录并链接 `ff_application.lib`；运行时部署 `ff_application.dll` 和 `CppDllMightyZap_Ver2010.dll`。只需包含 `<DX_FF.h>`。源码示例见 `examples/public_sdk/`；SDK 包内见 `examples/`。按任务阅读[应用场景指南](应用场景指南.md)，完整训练闭环见[Training 流程](Training计算流程.md)和[仿真示例](仿真示例.md)。

每一步都检查本次返回值。设备打开后，用 `refresh()` 或 `refresh_rod()` 更新反馈；只有 `RodPosition.valid` 为真时才能采用其位置。以下示例的 `config.json`、`slot_0.json` 是调用方提供的路径。

## 打开 → 单杆运动 → 关闭

```cpp
FF::ff_driver driver;
auto result = driver.open("config.json", FF::Mode::Simulation);
if (!result) { /* 记录 result.code 和 result.message */ return 1; }
result = driver.refresh();
if (!result || driver.m_current_positions.empty() ||
    !driver.m_current_positions.front().valid) { driver.close(); return 2; }
auto rod = driver.m_current_positions.front();
result = driver.move_rod(rod.address, rod.encoder); // 阻塞至到位稳定
if (!result) { /* 查看反馈，杆可能已有运动 */ driver.close(); return 3; }
driver.close();
```

需要异步下发时改用 `send_rod(address, encoder)`：成功只代表目标下发，随后用 `refresh_rod(address)` 轮询 `m_current_positions`、报警及状态。速度由配置的 `motor_parameters.speed_limit_raw` 在连接时为各杆设置。

## 打开 → 读取位置文件 → 多杆运动 → 关闭

```cpp
FF::ff_driver driver;
auto opened = driver.open("config.json", FF::Mode::Simulation);
if (!opened) return 1;
auto loaded = driver.load_positions("slot_0.json");
if (!loaded) { /* 查看 loaded.result */ driver.close(); return 2; }
// 本例 slot_0.json 必须覆盖全部启用杆；普通稀疏配方用 send_partial_rods() 后轮询。
auto moved = driver.move_rods(loaded.value.targets);
if (!moved) { /* 刷新并检查实际位置 */ driver.close(); return 3; }
driver.close();
```

`load_positions()` 返回当前启用且文件包含的目标与摘要，不运动、不保留待执行目标。普通配方可缺少整个通道，使用 `send_partial_rods(loaded.value.targets)` 并轮询至到位，缺失通道不接收命令。只有完整覆盖全部启用杆时才可直接传给 `move_rods()` / `send_rods()`；后者仅表示下发成功，仍需轮询实际反馈。训练目标须合入全部返回 Aim（包括避让项），并为其余杆提供保持位置。运动前会再次检查最新状态。

要保存修改后的目标集，可调用 `save_positions("preset.json", loaded.value)`；要记录设备当前反馈位置，调用 `record_positions("current.json", "摘要")`。两者均写入简洁的 `FF-POS-2` 文件，仅列实际记录的通道，每根杆独占一行。

`open()` 加载配置并连接，失败会清理连接。`record_positions(path, summary)` 仅在整机就绪且反馈安全时记录当前杆位。`close()` 失败时不能假定设备已断开。接口、类型、位置文件和错误码详见[接口参考](接口参考.md)、[数据结构参考](数据结构参考.md)、[位置文件格式](位置文件格式.md)、[错误码与状态](错误码与状态.md)、[安全边界及部署说明](安全边界及部署说明.md)、[升级说明](升级说明.md)。

## 初始化与 Training 入口

`open()` 不运动。正常训练前调用 `initialize("slot_0.json")`，检查结果及 `m_status.initialized`；slot0 必须覆盖全部启用通道的全部杆。首次调试可在初始化前手动运动并记录 slot0，不能每次开机覆盖。停止、急停、复位和断开会清除初始化标志。

需要任意物理通道组合时使用 `open(config, mode, ports, FF::ChannelSelection{true, false, true})`（CH1+CH3）。按 `machine_info().enabledChannels` 遍历物理通道，不能以通道数量替代物理编号。FF SDK 不负责 stage/TDI 控制和像素能量；真实联动时序见[Training 完整流程](Training计算流程.md)。

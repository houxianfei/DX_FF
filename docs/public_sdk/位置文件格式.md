# 位置文件格式

新保存的位置文件使用 `FF-POS-2`，保存机台身份、配置版本、摘要和编码器目标。Training 样本、候选与分配另存会话。完整使用步骤见[应用场景指南](应用场景指南.md)。

```json
{
  "schema": "FF-POS-2",
  "machine_id": "FF-001",
  "config_version": "FF-CONFIG-1.1",
  "summary": "CH1 recipe",
  "channels": [
    {"channel": 0, "execution_targets": [
      {"rod": 0, "position": 100},
      {"rod": 1, "position": 315}
    ]}
  ]
}
```

上述示例仅表示文件结构，不是通用机台合法位置。channel 为物理通道号 0/1/2，rod 为配置 ID，position 为整数 count。速度由配置 motor_parameters.speed_limit_raw 设置，目标不包含 velocity。

## 完整性和执行规则

- channels 只列实际记录的通道。出现的启用通道必须包含该通道全部杆，每杆恰好一次；缺少整个启用通道允许保持原地。未启用通道忽略并通过 PositionSet.ignoredChannels 返回。
- `load_positions()` 不运动，返回当前启用且文件包含的目标；检查机台/配置、限位和安全状态，运动前再次依据最新反馈检查。
- `send_partial_rods(loaded.value.targets)` 只向列出的杆发送，之后必须轮询确认到位。`move_rods()` / `send_rods()` 要求全部启用杆恰好一项，不能直接传入稀疏目标。
- slot0 用于 `initialize()` 时必须覆盖全部启用杆，普通配方的缺通道保持策略不适用。
- `save_positions()` 写调用方目标，允许缺整个通道；`record_positions()` 记录全部启用杆实际反馈，要求整机就绪、位置有效且无报警。两者均新写 FF-POS-2，不保存图像或扫描曲线。

## 旧文件兼容

FF-POS-1、旧 FF-TRAIN-1 位置文件，以及含 execution_targets 的 FF-TRAIN-1/2/3 会话可作为兼容输入；读取后仍需按当前机台反馈校验，历史训练建议重新分配后执行。旧 FF-POS-1 通常列出三个通道，空通道不作为该通道的有效目标集。重新保存为 FF-POS-2。

CSV 只读兼容，表头后为 channel,rod,position 或旧 channel,rod,position,velocity；velocity 被忽略。CSV 无机台身份，读取时绑定当前机台/版本，建议迁移 JSON。更多通道与初始化规则见[多通道说明](多通道升级.md)。

# 位置文件格式

位置文件使用独立的 `FF-POS-1` JSON。它只保存机台身份、配置版本、摘要和编码器目标；Training 的扫描样本、寻谷设置、分配过程等由 Training session 单独保存。`record_positions()` 记录当前反馈杆位；`save_positions(path, positions)` 保存调用方提供的完整目标集。GUI 的 `slot_N.json` 也使用此格式。

```json
{
  "schema": "FF-POS-1",
  "machine_id": "FF-001",
  "config_version": "FF-CONFIG-1.1",
  "summary": "Main UI Slot Initial",
  "channels": [
    {"channel": 0, "execution_targets": [
      {"rod": 0, "position": 0},
      {"rod": 1, "position": 315}
    ]},
    {"channel": 1, "execution_targets": [
      {"rod": 0, "position": 0}
    ]},
    {"channel": 2, "execution_targets": []}
  ]
}
```

`channels` 固定列出 `0`、`1`、`2` 三个通道；未启用或无记录的通道可为空数组。**已启用通道必须包含该通道的全部配置杆，每杆恰好一行**，上述示例中的空 CH3 只适用于未启用 CH3 的情形。`rod` 为配置中的 Rod ID，`position` 是编码器整数目标。目标不包含 `velocity`；速度由 SDK 的 `FF_MOTION_SPEED` 统一配置。

`load_positions(path)` 不运动，成功返回 `ValueResult<PositionSet>`：`value.targets` 为全部启用杆目标，`value.summary` 为摘要。读取时检查机台、配置版本、完整性、限位和安全状态；运动时再依据最新反馈检查。`save_positions()` 会在写入前检查完整目标集和安全规则；`record_positions()` 还要求整机就绪和反馈有效。两个写入方法都使用临时文件完成替换。

旧 `FF-TRAIN-1` JSON 位置文件，以及包含完整 `execution_targets` 的 `FF-TRAIN-1` / `FF-TRAIN-2` Training session，仍可由 `load_positions()` 读取，其中的 `velocity` 字段忽略；重新保存时写为 `FF-POS-1`。旧 `slot_N.csv` 只读兼容，表头后每行可为 `channel,rod,position` 或旧格式 `channel,rod,position,velocity`。CSV 没有机台身份，读取时绑定当前机台和版本，建议迁移为 JSON。

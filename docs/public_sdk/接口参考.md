# DX_FF.h 对象接口参考（SDK 1.0.1）

本文说明 `DX_FF.h` 中的 `FF::ff_driver` 对象接口。该头文件自动包含 `DX_FF_Types.h`；在 Visual Studio 中对声明中的类型按住 Ctrl 点击即可跳转到定义。字段详情见[数据结构参考](数据结构参考.md)。GUI 私有配置编辑代码不随 SDK 交付。

## 约定与结果

- `Address.channel` 为 `0..2`，对应 CH1..CH3；调用运动方法时还须小于 `open()` 的 `activeChannels`。`Address.rod` 为配置中的 Rod ID（`0..255`），不是 `rods` 数组下标。
- `position`、`encoder`、`actual`、`target` 和 `encoderAim` 均为编码器整数位置；后缀 `Mm` 表示光学毫米位置。毫米换算采用该杆配置的 `P0 + P1 × encoder`。`velocity` 使用机台配置定义的速度单位，必须参照对应杆的 `maxVelocity`。
- `Mode::Simulation` 使用模拟后端；`Mode::Hardware` 使用真实设备。模式仅在 `open()` 时选择。
- `Result` 包含 `code` 和 `message`，`if (result)` 仅在 `code == ErrorCode::None` 时为真。`ValueResult<T>` 包含 `value` 与 `result`；失败时不要使用 `value`。`m_last_error` 保存最近一次报告的结果，部分纯计算方法成功时也会清除先前错误。

| `ErrorCode` | 含义及常见来源 |
| --- | --- |
| `None` | 操作成功。 |
| `InvalidConfiguration` | 配置文件无法读取或配置校验失败。 |
| `NotOpen` | 操作要求设备已打开，或底层尚未就绪。 |
| `InvalidTarget` | 地址、目标数、位置、速度或位置文件目标不符合要求。 |
| `SafetyViolation` | 当前状态或目标组合未通过安全检查。 |
| `DeviceAlarm` | 设备报告报警。 |
| `Communication` | 与控制器通信失败。 |
| `Timeout` | 等待反馈或到位超时。 |
| `Busy` | 设备已打开、正忙或运动被停止。 |
| `BackendFailure` | 未归入上述类别的后端或文件操作失败。 |

错误码是公开层对底层错误的归并。具体原因以本次返回的 `message` 为准；不要依赖消息文本做程序分支。

## 数据结构

本文件侧重 `ff_driver` 对象。`Result`、状态、目标、规划和训练会话等类型定义见[DX_FF_Types.h 数据结构参考](数据结构参考.md)；`DX_FF.h` 已自动包含该头文件，使用对象时仍只需 `#include <DX_FF.h>`。

## 对象生命周期与状态

典型调用顺序是构造 `ff_driver` → `open()` → 可选 `initialize()` 或设置目标 → `plan_positions()` → `execute_positions()` → `close()`。对象不可复制。`close()` 后可再次 `open()`；析构时对象及其快照引用失效。

`m_config`、`m_status`、`m_last_error`、`m_current_positions` 和 `m_target_positions` 是 SDK 所持对象的常量引用，读取不执行 I/O。它们仅在驱动对象存活期间有效；一次操作或状态回调可能改变引用所指内容。需要一致的长期记录时，调用方应复制快照。需要新反馈时先调用 `refresh()`。

| `DeviceStatus.state` | 来源与解释 |
| --- | --- |
| `Offline` | 初始或成功关闭后的状态；底层报告离线时也使用此值。 |
| `Ready` | 底层报告整机就绪。记录位置要求此状态且启用通道安全。 |
| `Moving` | 底层报告运动中。 |
| `Fault` | 底层报告故障。 |
| `EmergencyStopped` | 底层报告软件急停状态。 |
| `Other` | 当前公开映射未单列的底层状态，包括 `Initializing`、`Degraded`；不能据此推断设备已就绪。 |

这些字符串是最近状态快照，不是调用方可直接驱动的独立状态机。`open()` 加载配置并连接；失败会清理已连接资源。`initialize()` 加载 Slot 0 并执行运动；运动中可由另一线程调用 `stop()` 或 `emergency_stop()` 中断等待。故障排除后可调用 `reset_faults()`，随后刷新并检查实际状态。`close()` 成功后清空配置、位置快照并将状态设为 `Offline`；若断开失败，返回错误，不能假定已关闭。

状态回调接收更新后的 `DeviceStatus`。不要在回调中重入同一对象。除运动期间用于中断的停止操作外，同一对象的调用应按顺序执行；另一线程刷新或关闭时也不要同时读取快照。`set_status_callback()` 可在打开前注册，传入空回调可取消注册。

## ff_driver 方法

下表中“刷新”指主动读取设备反馈；“目标”指 `m_target_positions`；“运动”指向后端下发运动。常规返回 `Result` 的方法失败时应检查返回值和 `m_last_error`，并按需 `refresh()`；失败不代表硬件仍处于原位。

| 方法 | 前提、返回值与副作用 |
| --- | --- |
| `open(configPath, mode, ports = {}, activeChannels = 3)` | 要求尚未打开；读取并验证配置、创建后端并连接，返回 `Result`。`activeChannels` 指前几个启用通道；硬件模式须提供相应串口。成功时设置配置、状态、当前位置及待执行目标快照；失败时清理连接，不下发运动。重复打开返回 `Busy`。 |
| `initialize(slot0Path)` | 要求已打开；先按 `load_positions()` 校验并提交 Slot 0 目标，再按 `execute_positions()` 刷新、规划和阻塞执行。返回 `Result`。加载失败保持旧目标；执行失败时目标可能已提交且设备可能已部分运动。 |
| `close()` | 断开后端，返回 `Result`；未打开时调用也成功。成功后清空配置及位置并置为 `Offline`；断开失败时保留错误并应重新检查状态。 |
| `refresh()` | 要求已打开；读取反馈并更新 `m_status`、`m_current_positions`，返回 `Result`。不改变待执行目标，不下发运动。 |
| `refresh_rod(address)` | 要求已打开；只刷新指定杆反馈，再更新公开状态快照。不下发运动。 |
| `machine_info()` | 返回当前配置的只读机台信息；不执行 I/O，不开放配置修改。 |
| `set_status_callback(callback)` | 注册或清除状态回调；返回 `void`，并将最近错误置为成功。不下发运动。回调中不得重入驱动对象。 |
| `load_positions(path)` | 要求已打开；读取位置文件，核对机台、配置版本、完整杆集合及目标安全性。成功时原子替换待执行目标；失败保持旧目标。返回 `Result`，不下发运动。 |
| `m_position_summary` | 最近一次成功加载的位置文件摘要；打开、关闭时清空。 |
| `record_positions(path, summary = {})` | 要求已打开且整机 `Ready`；刷新当前反馈，检查启用通道安全及杆反馈，再写位置文件。返回 `Result`；不改变待执行目标，不下发运动。 |
| `set_target_position(address, encoder, velocity)` | 要求已打开；验证地址、编码器软硬限位及速度，成功时仅更新一根杆的待执行目标。返回 `Result`；失败保持目标，不刷新反馈，不下发运动。 |
| `set_target_positions(targets)` | 要求已打开且提供每根启用杆恰好一个目标；逐项校验地址、重复项、限位和速度，成功时整体替换待执行目标。返回 `Result`；失败保持旧目标，不刷新反馈，不下发运动。组合安全仍由规划或执行时检查。 |
| `validate_target_positions(targets)` | 刷新反馈并由 SDK 校验目标组合，不提交目标也不下发运动；返回 `Result`。 |
| `plan_positions()` | 要求已打开且待执行目标有效；刷新反馈、校验完整目标及安全规则，返回 `ValueResult<Plan>`。不改变目标，不下发运动；失败时 `result` 含错误。 |
| `execute_positions()` | 按当前待执行目标重新刷新、校验、规划并阻塞执行，返回 `Result`。设备可能在失败前完成部分步骤；完成后应刷新状态核实。 |
| `send_positions()` | 对已提交的完整待执行目标进行 SDK 安全校验并下发，不等待逐杆到位；用于需要自行刷新反馈的界面。返回成功仅表示下发成功，随后必须检查状态。 |
| `move_rod(address, encoder, velocity)` | 要求已打开；校验单杆目标及邻杆相关安全条件，直接下发并等待到位，返回 `Result`。成功时更新该杆待执行目标；失败时不保证实际位置仍是调用前位置。 |
| `send_rod(address, encoder, velocity)` | 要求已打开；由 SDK 校验单杆及相关安全条件后下发目标，不等待到位。调用方可用 `refresh_rod()` 轮询反馈，并以 `stop()` 中断。 |
| `stop()` | 要求已打开；请求取消运动，返回 `Result`。不等于硬件急停；被中断的运动可能返回 `Busy`。 |
| `emergency_stop()` | 要求已打开；请求软件急停，返回 `Result`。不能代替硬件急停回路。 |
| `reset_faults()` | 要求已打开；请求清除设备故障，返回 `Result`；之后应刷新并确认状态。 |
| `assign_training(channel, candidatesMm, excludedRod = -1)` | 要求已打开且通道有效；刷新反馈，计算 Layer 2 候选点分配，返回 `ValueResult<Assignment>`。`-1` 表示不排除杆；不改变目标，不下发运动。 |
| `simulated_energy(source, positionMm, startMm, endMm)` | 为模拟训练生成指定位置的能量值；不控制设备。 |
| `interpolate_energy(samples, positionMm)` | 对样本能量在给定毫米位置插值，返回 `double`；不要求已打开，也不下发运动。 |
| `find_valleys(samples, settings)` | 根据样本及谷值参数返回毫米位置数组；不要求已打开，也不下发运动。 |
| `drag_interval(candidatesMm, movingIndex, anchorMm, scanStartMm, scanEndMm, windowWidthMm = 3.0)` | 计算一个候选点的可拖动毫米区间，返回 `DragInterval`；只有 `valid` 为真时使用边界。不要求已打开，也不下发运动。 |
| `save_session(path, sessionJson)` | 使用 `FF-TRAIN-1` 解析器先验证传入 JSON，再写入会话文件，返回 `Result`；不要求已打开，不下发运动。实现会短暂使用 `path + ".validate.tmp"`。 |
| `load_session(path)` | 先解析校验 `FF-TRAIN-1` 文件，再返回原始 JSON 文本，类型为 `ValueResult<std::string>`；不要求已打开，不下发运动。 |
| `save_training_session(path, session)` / `load_training_session(path)` | 结构化读写 `TrainingSession`，并复用 SDK 的 `FF-TRAIN-1` 文件格式与校验；不下发运动。 |
| `version()` | 返回 SDK 版本字符串（当前 `1.0.1`）；不要求已打开，不访问设备。 |

安全限制、位置文件格式和 Training 工作流程分别见[安全边界及部署说明](安全边界及部署说明.md)、[位置文件格式](位置文件格式.md)和[Training 计算流程](Training计算流程.md)。

# Training 仿真闭环示例

`training_sim.cpp` 只链接 FF SDK，运行时固定使用 Simulation。它演示初始化、300 点多通道采样、寻谷、排除训练杆的分配、全部 Aim 合成、执行、保存/回读会话及杆位配方复用；不调用 stage/TDI，不做光学效果验收。

源码目录为 `examples/public_sdk/`；SDK 包内为 `examples/`。使用专用 `training_config.sim.json` 和 `training_slot_0.json`，不要与旧 `main.cpp` 的单杆配置混用。每通道包含独立的 Layer 2 杆 0、1：杆 0 扫描，杆 1 承担候选任务；软范围 10–90 count，P0/P1 默认 0/1，稳定时间 20 ms，超时 1000 ms。此独立杆模型仅供仿真，未描述真实机台机械邻接，不能用于硬件。

## 编译与运行

在 VS2019 的 **x64 Native Tools Command Prompt** 执行。SDK 包根目录内，Release 示例命令如下；Debug 时使用匹配的 Debug 库与 DLL，并将 `/MD` 改为 `/MDd`。

```bat
cl /nologo /EHsc /std:c++17 /utf-8 /MD /I include examples\training_sim.cpp /Fe:training_sim.exe /link /LIBPATH:lib\x64\Release ff_application.lib
set "PATH=%CD%\bin\x64\Release;%PATH%"
training_sim.exe examples\training_config.sim.json examples\training_slot_0.json result_training 7 forward valleys
```

源码工作区先构建匹配 SDK，再在仓库根目录编译运行：

```bat
msbuild ff_application.vcxproj /p:Configuration=Debug /p:Platform=x64 /p:ImportUserProps=false /m
cl /nologo /EHsc /std:c++17 /utf-8 /MDd /I include examples\public_sdk\training_sim.cpp /Fo:x64\Debug\training_sim.obj /Fe:x64\Debug\training_sim.exe /link /LIBPATH:x64\Debug ff_application.lib
x64\Debug\training_sim.exe examples\public_sdk\training_config.sim.json examples\public_sdk\training_slot_0.json result_training 7 forward valleys
```

确保 `ff_application.dll` 和 MightyZap 运行时 DLL 位于 exe 同目录或 PATH。输出目录的父目录必须存在，输出目录本身必须不存在，以避免覆盖旧运行。示例不修改输入文件。

## 参数和预期结果

```text
training_sim <config> <slot0> <new-output-directory> [mask] [direction] [profile]
```

| 参数 | 规则 |
| --- | --- |
| mask | 默认 7；1=CH1，2=CH2，4=CH3，按位相加，范围 1–7；5 表示 CH1+CH3 |
| direction | forward（默认）：softMin 至 softMax；reverse：反向。光学方向受 P1 符号影响 |
| profile | valleys（默认）：Sim1 仿真能量；flat：固定能量，用于演示无候选 |

成功退出码为 0，打印每启用通道的样本数和候选数。输出 `training.json`（FF-TRAIN-3）与 `positions.json`（FF-POS-2），仅包含启用通道；会话各通道有 300 个样本，候选上限为 1。flat 应无候选，不宣称有效遮挡优化。最终回放的是另存的完整位置配方，不直接回放历史会话目标。

失败返回非零并保留本次错误；设备已连接时尝试 stop、保存 partial_training.json（会话已建立时）、close，分别报告清理失败。complete 只表示扫描完成；分配/执行阶段失败不应将完整扫描误标为缺样本。示例通过异常路径展示失败清理，不实现交互式取消或断点续扫。

## 验证场景

每次使用新的输出目录：

| 场景 | 参数/输入 | 核对项 |
| --- | --- | --- |
| 单通道 | 1 forward valleys | CH1 有 300 点，只有 CH1 文件记录 |
| 多通道 | 7 forward valleys | 三通道各 300 点、寻谷分配、执行和回读成功 |
| 非连续通道与反向 | 5 reverse valleys | 只记录 CH1/CH3，首末位置反向，实际反馈与能量配对 |
| 无候选 | 2 forward flat | CH2 完整扫描、候选为空、无候选目标保持当前位 |
| 初始化失败 | 缺失或不完整 slot0 | 返回非零，不进入扫描，不生成成功会话 |
| 分配失败 | 仿真配置删除杆 1，slot0 同步删除杆 1 | 扫描数据保留，候选超过可分配杆数时失败，记录部分产物而不执行旧计划 |
| 保护旧数据 | 重用输出目录 | 返回非零，不覆盖既有记录 |

运动/采集超时、坏帧、外部取消和急停的设备联调依据见[Training 完整流程](Training计算流程.md)。仿真示例不能验证 stage/TDI 时序或真实机械及光学安全。

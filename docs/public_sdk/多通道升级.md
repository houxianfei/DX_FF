# FF SDK 多通道使用说明

`ChannelSelection` 是三个布尔值，依次对应 CH1、CH2、CH3。可以选择任意非空组合。旧版 `open(path, mode, ports, activeChannels)` 保留，`activeChannels=1/2/3` 分别表示从 CH1 起启用的前 N 个通道；不在该范围内的值直接返回配置错误。`machine_info().enabledChannels` 返回实际组合。

`open()` 只验证配置和建立连接。绝对式电机无需寻零。连接后调用 `initialize(slot0Path)`，SDK 会检查 slot0 的机台及配置版本、全部启用通道和电机的目标、所有反馈及报警，再统一规划、运动，并等待全部目标按容差和稳定时间到位。只有成功时 `m_status.initialized` 为真；断开、停止、急停和故障复位会清除该标志。GUI 在后台运行初始化，等待过程中可以停止或急停。

配置 JSON 可仅列出实际配置的 1–3 个通道。启用的通道必须有电机及完整层归属；每对相邻杆必须有非负间隙规则。单独杆使用 `role: 3` 且邻居均为 `-1`。速度、加减速度、到位容差、稳定时间和运动超时为所有电机共享参数。文件解析会拒绝语法错误、重复字段、错误类型、越界整数以及不一致的杆级运动参数。未启用通道不连接，也不参与反馈和运动。

普通位置文件新写为 `FF-POS-2`，`channels` 只列实际记录的通道。出现的启用通道必须包含全部电机，缺少整个启用通道时该通道保持原地；未启用通道的目标被忽略。`load_positions()` 返回当前启用且文件中存在的目标。初始化用的 slot0 则必须覆盖全部启用电机。旧 `FF-POS-1`、CSV 和训练文件仍可读取。

多通道 Train 新写为 `FF-TRAIN-3`，包含启用通道掩码、采样数量以及每个启用通道的会话。默认采样数量为 300，各通道可以使用不同起终点；每轮等待所有通道到位后一起记录。旧 `FF-TRAIN-1/2` 仍可读取，新扫描不会使用旧的 `step_mm` 控制位移。真实 Itek 相机采集仍未接入。
